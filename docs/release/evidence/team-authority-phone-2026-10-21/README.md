# Parent Access Removal And New Admission On A Phone

Five observed stages passed on one physical Google Pixel 9 / Android 15 on
21 October, using only the isolated demo backend. The exact APK is the previously
uploaded 458318c build; no app/backend deployment or production write occurred.
The controller's executed working-tree bytes and service sources are archived
by digest, without claiming they were already in that APK's source commit.

The parent initially sees only the message after their admission. A separately
authenticated manager service revokes their verified parental link. The open
phone conversation hides its messages and composer on its next check, while the
independent service read is denied. Authenticated parent/manager service requests
then renew the link. Tapping Actualiser reopens an empty conversation: neither
earlier message returns. A new driver service message becomes visible, and one
explicit parent UI send produces exactly one new reply.

Five independent checkpoints verify parental revisions 2, 3 and 5, exact visible
message IDs, four final messages/operations, the other parent's unchanged access
and 158 protected records with original claims. The fixture controller does not
send the parent's reply or mark reads. Manager/parent verification decisions use
services, not management/request screens. No simultaneous second phone is used.
