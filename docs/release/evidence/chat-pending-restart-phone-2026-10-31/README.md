# Pending Message Restored After Force-Stop

31 October 2026, one physical Google Pixel 9 Pro / Android 15.0. Synthetic parent
and driver accounts, an isolated free booking and four private loopback services.
No production account, real payment, map request, invitation port or alias is used.
The selected existing APK matches its retained local SHA-256; installed remote
bytes and the whole current APK are not independently attested. Six critical
conversation/draft sources are byte-identical to the APK's source commit.

## Observed Flow

The parent opens the fixture's empty conversation. The device's controlled
Offline Mode is applied before one send. The app shows an unconfirmed-send error
and retains the original text. Independent records contain no message or chat
notification. Android's own App info shows the enabled Force stop action, its
confirmation dialog, and the disabled action after confirmation. No app data is
cleared or APK reinstalled. The provider refuses the read-only `pidof` command;
independent process IDs and process birth are therefore not accepted.

Opening the installed app while still offline shows a session-restoration error.
After disabling network simulation, one explicit session retry returns the same
parent's Home without entering credentials. Reopening the same booking restores
the pending text and error. Tapping the pending field does not open the keyboard.
The seven pre-message-retry checkpoints still contain zero messages and zero
chat notifications. There is no automatic send during this observed interval.

One explicit message retry then produces one confirmed bubble and an empty
composer. The independent service records contain exactly one message, one
addressed notification and two consistent conversation indexes, without a
duplicate. The final sign-out checkpoint preserves those records. All unrelated
documents, account claims and live-trip data stay unchanged, apart from the
documented parent initialization timestamp. The observer submits no chat message.

## Evidence And Cleanup

Nine ordered stored-state checkpoints and ten original 216 by 458 session-window
crops are retained. Only the interrupted, restored and confirmed message crops
are published. They are native browser screenshot clips, not native-device
exports, reconstructed images or video. Every earlier gallery, tour and date
stays available. The attempted video does not start; its provider modal requests
screen-sharing permission. The underlying cause is not independently established,
and no permission is changed or Chrome restarted.

The initial helper handoff fails during private input. A later clipboard read is
empty; a direct private credential transfer then succeeds, with the key remasked.
These observations do not establish the first handoff's exact root cause. No key
is printed or rotated. Remote keyboard punctuation and text are corrected before
the first actual send, rather than treating input errors as app failures.

The parent signs out and network simulation is visibly off. The uninstall action
reports no user apps found; this is not successful uninstall or package-absence
proof. The phone session is explicitly ended and the idle dashboard is observed.
The browser clipboard is cleared; restoration of its original host contents is
not independently verified. Observer, backend and helper stop; their processes,
private session, copied runtime, handoff directories and four listeners are
independently absent. No device-administrator policy was changed.

## Remaining Scope

The cutoff occurs before a server commit, not after a committed message loses its
reply. The original pending request UUID is not independently read before/after
the phone restart. This accepts the observed pending-text recovery and single
explicit pre-commit retry, not post-commit deduplication, account switching with a
pending send, another phone's UI, real-world radio loss, push, tracking, iOS,
production deployment or release readiness. Messages remains partial; public Site
access stays unchanged. No infrastructure resource or Terraform change is needed.
