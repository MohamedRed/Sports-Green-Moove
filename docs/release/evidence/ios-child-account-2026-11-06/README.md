owned callable boundary. A parent selects a server-verified child through the
existing contact picker; the fresh contact response supplies the immutable child
instance. Parent roles, membership and guardian authority remain server-owned.
No privileged role or client-written account link is introduced.

origin/path/fragment and SHA-256 fingerprint, and are never reconstructed by a
status refresh. An explicit action presents the system share chooser. Claimed
signups cannot be replaced or revoked. Unknown create replies require explicit
refresh. Pairing approval is separate from invitation creation. Pure-child
accounts generate the existing short-lived code even without a current ride or
location permission. No email, real signup, provider request or production write
was exercised in this work.
