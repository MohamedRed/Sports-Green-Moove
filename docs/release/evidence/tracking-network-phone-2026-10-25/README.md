# Physical Phone Network-Loss Attempt

25 October 2026. Same isolated a5c7119b localhost APK, based on f3aef02 with the
native capture-clock repair later committed at c6635a0. Its six changed main-app
source snapshots still match. Fresh Pixel 9 Pro / Android 15 session and fresh
owned local backend; no production accounts, payments, route requests or app
deployment. Position and network loss are simulated, not an outdoor journey.

The phone starts one free booked ride. Offline mode is applied in the device
toolbar; GPS B is selected while disconnected. The observer measures 50 seconds
with no live-trip change. The app retains the active ride and shows an old-
position warning. Normal networking is restored and B arrives with newer capture
and upload times, without starting another ride.

**Display recovery fails.** Although uploads resume, the app keeps showing the
older position. A separate read records a fresh backend point while the screen
is roughly ten minutes old. Leaving and returning to the same app refreshes the
screen once; it then grows stale again despite continuing uploads. This is not
an accepted continuous-display or network-recovery flow. The cause is not yet
established; do not substitute polling, a fake listener or a receipt-time fix.

The independent observer completes all seven record-only checkpoints. This does
not assert phone UI success. Sign-out returns to empty login fields, and another
simulated location does not change the stored live trip during a fresh measured
50-second watch. All unrelated root records, bookings and claims remain equal to
baseline. Both Admin/Firestore clients close. The initial observer launch fails
before fixture seeding because its output parent directory is absent; the parent
is then created and the actual recorded observer starts. No completed flow is
claimed for that preparation error.

Three reviewed original 253 x 564 viewport JPEGs show the warning, the manual
return and the subsequent stale display. Other originals are retained separately,
not promoted to native-resolution exports or video. Maps are unconfigured. The
database log filter is inconclusive; its retained sanitized output does not prove
a listener error or an absent error.

Network simulation is explicitly off before session disposal. The uninstall
action reports no user apps; independent package absence is not proven. The
session returns to the idle dashboard, the owned helper exits, the private
handoff/session/runtime are removed and all four loopback ports are bind-tested.
No release scenario, child/parent-phone tracking, GPS-loss condition, screen-lock,
process restart, battery-saver or real provider integration is accepted.
